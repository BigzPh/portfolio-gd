glot

On-Device Real-Time Screen Translator

Lead Android Engineer Jetpack Compose Google ML Kit

Project Overview

glot is an Android accessibility service designed for real-time, on-device translation of any application screen. Combining MediaProjection for frame capture with Google ML Kit for OCR and Neural Machine Translation, it renders translation overlays directly on the active interface without transmitting screen data externally.

Technical Architecture

Concurrency

Kotlin Coroutines & StateFlow for reactive state propagation between background service and alert window UI.

Graphics

MediaProjection API & ImageReader (RGBA_8888 buffer) for optimized bitmap manipulation and downscaling.

Models

Offline-first script-specific OCR packages (Latin, CJK, Devanagari) and local Google Translate models.

Engineering Challenges & Solutions

Eliminating Overlay Jitter

Problem: Raw OCR coordinates float dynamically by several pixels between frames, creating flickering tooltips during active renders.

Solution: Custom linear interpolation tracking using a Smoothing Factor (0.55) combined with a Hysteresis Threshold. The position locks if shifts fall below a deadzone threshold; otherwise, tooltips slide using weighted averages.

OCR Feedback Loops

Problem: The OCR scanner detects the text of its own translated overlay tooltips as new foreign text, triggering nested translation loops.

Solution: Implemented a geometry exclusion map. The foreground service tracks active alert tooltip bounding boxes and intersects them with raw OCR output, filtering out overlapping detections.

Performance Optimization

Problem: Capturing and processing high-resolution screenshots at 60 FPS is CPU and battery intensive.

Solution: Developed a 65% image scaling pipeline directly in the RGBA buffer before sending frames to ML Kit, reducing memory footprint and processing cycles by over 50%.

Lapi

Offline-First Task Manager, Planner & AI Assistant

Lead Developer Jetpack Compose Local LLM (llama.cpp) Android & iOS

Project Overview

Lapi is an offline-first task manager and habit tracker published on Google Play and the App Store. It combines daily scheduling, habit tracking with activity heatmaps, recurring routine builders, and on-device AI planning using a quantized local LLM, keeping user data local and private.

Technical Architecture

On-Device LLM

Embedded C++ llama.cpp running quantized SmolLM2 GGUF models directly on-device for zero-latency, private AI chat & schedule generation.

Reactive Persistence

SQLite via Room Database 2.8.4 paired with Kotlin Coroutines & Flow combinators for atomic, multi-table reactive UI updates.

Camera Notch Capture

Android Accessibility Service listening on notch touches with physics-based droplet and overshoot animations for system-wide quick task entry.

Engineering Challenges & Solutions

On-Device LLM Memory & Thermal Constraints

Problem: Running local neural language models on mobile devices caused severe memory spikes, thermal throttling, and garbage collection pauses.

Solution: Compiled a native C++ JNI bridge linking llama.cpp with ARM NEON / KleidiAI acceleration. Utilized 4-bit quantized GGUF weights with aggressive token streaming and background thread isolation.

Hardware-Agnostic Cutout Geometry Detection

Problem: Different manufacturers implement varied punch-hole, pill, and teardrop camera cutouts, causing touch coordinates to misalign.

Solution: Leveraged WindowInsetsCompat.displayCutout to query real-time physical cutout bounding boxes and combined it with touch-slop hysteresis to trigger the smooth drop-down task input drawer reliably.

Conflict-Free Cloud Synchronization

Problem: Syncing local SQLite databases with Google Drive AppData snapshots across multiple devices resulted in overwritten tasks and broken streak counters.

Solution: Engineered a custom LapiSmartMerge engine. It performs entity-level timestamp reconciliation using monotonic updatedAtMillis and merges routine completion maps granularly.

Paddi

Sticky Notes Widget, Voice Memos & Companion

Lead Developer Compose Multiplatform SwiftUI & WidgetKit Android & iOS

Project Overview

Paddi is a home screen sticky notes widget and audio memo app published on Google Play and the App Store. Built with Kotlin Multiplatform and Compose Multiplatform, it shares business logic and UI between Android and iOS while integrating native home screen widgets.

Technical Architecture

Compose Multiplatform

Shared Kotlin business logic, state handling, and declarative UI across Android and iOS targets.

Dual-Platform Widgets

Native iOS WidgetKit extensions built in Swift with App Intents paired with Android AppWidgetProvider & RemoteViews.

Hardware Audio Pipeline

Cross-platform audio recording and playback utilities allowing users to record voice memos and play them back right from the home screen.

Engineering Challenges & Solutions

Cross-Platform Home Screen Widget Synchronization

Problem: iOS WidgetKit and Android RemoteViews have fundamentally distinct lifecycles, memory limits, and background refresh constraints that cannot run standard Compose UI directly inside the widget process.

Solution: Architected dedicated native bridge layers. On iOS, Swift WidgetKit extensions read from a shared App Group container updated by Kotlin Native; on Android, AppWidgetProvider observes local database changes, guaranteeing instant widget sync on both systems.

Adaptive High-Contrast Dynamic Typography

Problem: Sticky notes allow custom user-selected pastel and vibrant background colors, which often resulted in illegible text when colors clashed with standard black or white fonts.

Solution: Developed a real-time relative luminance calculation engine conforming to WCAG 2.1 contrast ratios (computing 0.2126R + 0.7152G + 0.0722B), with a manual high-contrast toggle for complete personalization.

Reactive Mascot Animation Frame Performance

Problem: Continuous vector animations, eye-blinking, and emotional reactions caused frequent recompositions and battery drain during fast typing.

Solution: Designed decoupled Compose transition specs with state-driven blink intervals and deferred canvas drawing passes, keeping UI rendering at 60 FPS with minimal CPU overhead.

Common Ground Coffee House

Typography Woodtype Sans Font Pairing Editorial Layout

Project Overview

An editorial poster study centered on pure typographic hierarchy, contrast, and tone of voice for Common Ground Coffee House. The project investigates how intentional font pairing and structural cadence can communicate craftsmanship, aroma, and community warmth without visual excess.

Typographic Hierarchy & Pairing Anatomy

Primary Headline (Woodtype Sans)

Heavy condensed uppercase letterforms with bold vertical stress, evoking the heritage of artisan woodblock printing and roasted espresso body.

Expressive Script (& Ampersand)

Dynamic sloping Italian script ampersand serving as a visual bridge, adding organic curvature and welcoming human warmth.

Secondary Editorial Grid

Structured geometric sans-serif supporting lines with calibrated tracking and open counters, ensuring effortless legibility from distance.

Earthy Roast Palette

Warm terracotta amber (#E88939), deep espresso roast (#3D2314), toasted caramel (#F49D56), and creamy parchment (#FAF3E8).

Design Principles & Composition Strategy

Harmonizing Industrial Weight & Organic Script

Challenge: Pairing an ultra-heavy, rigid condensed woodblock typeface with delicate cursive without making either feel out of place.

Execution: Scaled the script ampersand to overlap negative space within the condensed headlines, creating an integrated typographic lockup where the curves soften the heavy vertical bars.

Spatial Cadence & Negative Space

Challenge: Retaining high visual impact on an A3 print poster without overcrowding the composition.

Execution: Framed the central typographic lockup with generous breathing room and warm gradient vignette edges, focusing the viewer's eye straight toward the primary message.

BiteFlow

Mid-Fidelity Online Ordering & Delivery System

Figma Prototype Mobile UI/UX Mid-Fidelity Wireframes Usability Principles

Problem Identification & Target Users

Target Users: Busy urban professionals, college students, and households who frequently order meals online and prioritize speed, pricing transparency, and straightforward navigation.

Problem Addressed: Traditional food delivery apps suffer from visual clutter, aggressive pop-ups, hidden service fees revealed only at final checkout, and confusing food customization options that drive high cart abandonment.

The Solution: Clean mid-fidelity mobile wireframes eliminating decorative noise to focus strictly on intuitive restaurant discovery, structured constraint-based customization, upfront fee breakdowns, and real-time order status tracking.

Core Screen Architecture & User Flow

Screen 1: Home & Discovery

Address verification, quick search, horizontal cuisine chips ([All], [Burgers], [Pizza]), and transparent rating/fee cards.

Screen 2: Food Customization

Separates mandatory single-choice radio buttons (Bun) from optional checkbox add-ons, with sticky dynamic total bar.

Screen 3: Cart & Review

Itemized quantity steppers, address confirmation, multi-channel payment (GCash / COD), and transparent bill breakdown.

Screen 4: Order Status & Tracking

4-stage stepper tracker (Confirmed → Preparing → On the Way → Delivered) and instant driver communication (Call/Message).

UI/UX Principles & Usability Heuristics

Visual Hierarchy & Transparent Costing

Goal: Eliminate surprise fees and high cart abandonment during checkout.

Execution: Important item titles, prices (₱180), and sticky primary CTAs use bold typography and high-contrast containers. Secondary metadata (ratings, delivery fees) uses lighter gray line weights, guaranteeing upfront transparency.

Error Prevention & Selection Constraints

Goal: Prevent order mistakes and conflicting customization options.

Execution: Strict separation of circular radio buttons for mutually exclusive required selections (buns) versus square checkboxes for multi-select extras. The sticky bottom bar updates the total in real time ([ Add to Cart - ₱205 ]).

Visibility of System Status & Feedback

Goal: Keep users informed and confident post-purchase without anxiety.

Execution: A prominent 4-stage stepper status bar provides clear visual feedback of the order lifecycle phase, estimated arrival window, and rider contact shortcuts.
